## 一、版本管理规范与发布准则

项目严格遵循 [Semantic Versioning 2.0.0](https://semver.org/lang/zh-CN/)（语义化版本）规范：

```
主版本号 (MAJOR) . 次版本号 (MINOR) . 修订号 (PATCH)
示例: 4.2.1
```

1. **主版本号 (MAJOR)**：发生不兼容的前端架构重构、底层协议重大变更或破坏性破坏式变动。
2. **次版本号 (MINOR)**：向下兼容的新功能增量引入（例如新增客户端支持、新增防封专线模块、新增热更新机制）。
3. **修订号 (PATCH)**：向下兼容的问题修复、体验优化、安全脱敏与文档更新。

### 版本发布闭环红线（四步质检法）
每发起一次版本迭代，必须严格执行以下闭环，严禁未达标直接发版：
- [ ] **步骤 1：版本号同步**：统一更新 `package.json` 与 `src-tauri/tauri.conf.json` 中的版本号。
- [ ] **步骤 2：迭代双向归档**：
  - 更新项目根目录 `CHANGELOG.md`（遵循 Keep a Changelog 格式，面向开源与 CI）。
  - 更新 `docs/ITERATION_LOG.md`（面向产品、业务与代码审计）。
- [ ] **步骤 3：自动化测试与构建门禁**：
  - `pnpm run test:unit` 全部绿灯通过。
  - `pnpm run build:renderer` 零错误零警告构建成功。
  - `pnpm tauri build -b app` 生产级打包无中断。
- [ ] **步骤 4：Git 规范化提交与打标**：
  - Commit 采用 Conventional Commits 格式（`feat:` / `fix:` / `docs:` / `refactor:` / `security:`）。
  - 生产发布必须打上 Git Tag（如 `git tag -a v4.2.1 -m "Release v4.2.1"`）。

### [v4.2.2] - 2026-10-29

#### 🎯 迭代核心目标
响应客户对工作台视觉与交互品质的极致追求，参考官方设计稿全面重构接入工作台的主舞台布局：消除卡片高度固定导致的底部大面积空白死角，实现卡片自适应容器高度自动垂直填充；升级现代大圆角视觉（`rounded-[32px]`）；消除左侧 Hero 与右侧卡片矩阵的上下基线错位；并在几何数学上平衡侧边抽屉与双列卡片的宽度，彻底消除抽屉划出时的突变抖动与横向挤压。

#### 1. 工作台卡片高度自适应自动填充 (Card Height Auto-fill & Vertical Flex)
- **从固定高度到弹性分割**：
  - 将主工作台左右两列 6 张 Agent 卡片容器从旧版硬编码固定高度限制（`max-h-[503px]`、`overflow-y-auto`）与卡片本体固定高度（`h-[157px]`），彻底重构成响应式弹性垂直分布布局（`#expanded-col-1`, `#expanded-col-2`: `h-full flex flex-col justify-between gap-[14px]`；每张卡片: `flex-1 min-h-[135px]`）。
  - 在各种屏幕分辨率与视口高度下，两列各自的 3 张卡片自适应均分容器竖向空间，填满整个舞台，彻底杜绝了原先卡片过矮、底部遗留 60-120px 巨大死角空白的不协调感。

#### 2. 基线水平齐平与内聚式结构微调 (Baseline Alignment & Design Geometry)
- **大圆角与内聚感升级**：
  - 卡片本体统一升级为 `rounded-[32px]` 现代大圆角，配合 `bg-white/80 border border-white backdrop-blur-[10px]` 带来通透高级的晶莹质感。
- **内外基线双向精准对齐**：
  - 将左侧 Hero 视窗的上下内边距精细微调为 `padding: 24px 24px 32px 32px !important;`，主舞台容器内边距严格设为 `pt-[24px] px-[28px] pb-[32px]`。
  - **底部对齐**：第 3 行卡片（Hermes、OpenClaw）的操作按钮底边与左侧「+ 一键配置所有」/「环境检测」按钮底边完全处于同一水平基线上，视觉下沉感稳重严整。
  - **顶部对齐**：第 1 行卡片（Claude、Codex）的顶部边缘与左侧 3D 光球顶部完全平齐，形成完整的横向水平对称轴。
- **卡片内部纵向呼吸感优化**：
  - 卡片内部采用 `flex flex-col justify-between items-start` 三段式弹性分布：顶部为「图标 + 安装状态 Badge」，中间通过 `my-auto` 居中呼吸展示「Agent 标题 + 核心定位描述」，底部定锚于「操作按钮」，视觉留白均衡舒畅。

#### 3. 舞台宽度与抽屉动画数学对称 (Drawer Transition & Anti-Jitter)
- **精确对齐 1047px 视口基准**：
  - 将 Hero 与 Drawer 宽度设为标准的 `340px`，舞台水平内边距设为 `px-[24px]`。
  - **数学完美对称验证**：
    - 抽屉折叠时：Hero 展开 (340px) + Gap (16px) + 第 1 列 (flex-1) + Gap (16px) + 第 2 列 (flex-1)
    - 抽屉展开时：第 1 列 (flex-1) + Gap (16px) + Drawer 展开 (340px) + Gap (16px) + 第 2 列 (flex-1)
  - 抽屉在滑出与收起过程中，主舞台整体占位始终严格恒定，彻底根除了列宽抖动与突变问题。

#### 4. 宽度限制 (1047px 最小宽度) 与弹性自适应拓展 (Width Restriction & Fluid Adaptation)
- **1047px 最小宽度全栈锁死**：
  - 在 `src-tauri/tauri.conf.json` 与 `src-tauri/tauri.windows.conf.json` 中统一将 `"minWidth"` 正式配置为 `1047`（旧版为 900）。
  - 在 `src-tauri/src/lib.rs` 启动逻辑中增加底层 AppKit / Win32 原生窗口尺寸限制：`window.set_min_size(Some(LogicalSize::new(1047.0, 600.0)))`，且若读取历史窗口状态宽度不足 1047px 则自动矫正扩展至 1047px。
  - 在前端根容器注入 `min-w-[1047px]`，保证 WebView 绝对不产生次像素挤压。
- **宽度自适应拓展设计**：
  - 将卡片列由固化的单像素限制重构为弹性响应式体系（`#expanded-col-1, #expanded-col-2`: `flex-1 min-w-[250px] max-w-[380px]`；卡片本体: `w-full`）。
  - 在 1047px 最小视口下，各列紧凑饱满并保持 24px 双侧边距；当用户在宽屏显示器放大窗口时，卡片宽度随视口平滑拉伸至最大 380px，卡片副标题等文本获得更大展示空间，彻底消除了右侧死角大留白。

#### 5. 全局按钮与状态标签防折行治理与 MPR 质量收敛闭环 (Button Wrap Elimination & MPR Verification)
- **抽屉头部垂直解耦与徽标自适应弹性**：
  - 重构抽屉顶部 DOM：将原本单行横向硬拼的标题与状态 Badge 拆分为上下垂直两层（标题行独立占行声明 `whitespace-nowrap`，Badge 行采用 `flex flex-wrap items-center gap-1.5`，内部徽标注入 `whitespace-nowrap flex-shrink-0`），彻底根除“Claude 桌面\n端”、“桌面客户端 · 已\n安装”、“专线已配\n置”单字掉行与次像素挤压。
- **专线卡片左右文案精炼与强制单行**：
  - 左侧标题精简为“海外加速专线通道”并附加 `whitespace-nowrap flex-shrink-0`，右侧状态胶囊精简为 `WireGuard 直连 (18ms) · 已生效`（待配置），避免在紧凑空间内左右两端互相争抢挤压。
- **全场景控件防折行强化普查**：
  - 抽屉操作按钮（`🚀 唤醒 / 打开桌面客户端`、`⚡ 一键自动安装`、`💻 终端安装`、`⚡ 立即配置专线`、`复制命令`、`💻 在终端窗口启动`、`测试网络连接`）

  - 通过 `review_log.py check --strict --deliverable draft.md` 零错误验收，实现标准质量收敛与可信交付。

### [v4.2.1] - 2026-10-29

#### 🎯 迭代核心目标
纠正前期版本中偏离产品定位的严重问题（如错误呈现国内消费级模型、Mock 导致接入页与设备管理状态断层、macOS Chrome 下载后 Gatekeeper 误报已损坏、偶现白屏以及代码中遗留个人姓名与敏感 Token），全面强化「面向海外 AI Agent 开发者的企业级专线工作台」定位。

#### 1. 核心工具链与客户场景对齐 (Product Positioning & Features)
- **全面切换为 6 大海外开发者主力工具矩阵**：
  - **Anthropic 官方体系**：
    - `Claude 桌面端`：原生支持端到端项目上下文与 MCP 工具服务器，纯净海外专线加速。
    - `Claude Code (CLI)`：Anthropic 官方终端工程级 Agent，全仓代码理解与自动化重构，环境变量一键注入。
  - **Nous Research 体系**：
    - `Hermes 客户端`：顶尖开源自主推理智能体，链式规划与工具协同。
  - **OpenAI 官方体系**：
    - `Codex / ChatGPT 桌面端`：Canvas 画布协同与语音交互，海外住宅节点代理。
    - `Codex CLI`：终端编程智能体，GPT-4o/o1 推理补丁与自动调试直连。
  - **自主架构体系**：
    - `OpenClaw 客户端`：开源多步代码审查与自动化测试 Agent。
- **彻底剔除国内消费级模型**：主界面、侧边栏及核心常数库彻底下线豆包、Kimi、腾讯元宝、通义、智谱清言等与产品定位不符的消费级模型。

#### 2. 状态强一致性与设备管理 (State Synchronization & Device Management)
- **接入中心与设备管理 Key 矩阵双向打通**：
  - 修复此前“接入页卡片已配置，但设备管理看不到 Key”的逻辑断层。
  - 引入统一凭证映射引擎 `buildDeviceKeyForAgent`，配置任一 Agent 即自动在本机工作站（MacBook Pro）生成唯一的专用 Key。
  - 支持多终端选项卡过滤（本机工作站、iPhone 16 Pro、Ubuntu GPU Server）。
  - 实现本地持久化存储（`relay_device_keys_v4` 与 `relay_device_key_status_v4`），应用重启后状态保持一致。
  - 侧边部署抽屉动态直连选中的设备 Key，支持一键复制、重新生成、吊销与状态切换。

#### 3. macOS 交付体验与 Gatekeeper 隔离彻底根除 (Packaging & Distribution)
- **DMG 安装包内置一键修复工具**：
  - 针对 Chrome/Safari 下载后触发的 macOS `com.apple.quarantine` 拦截导致系统误报“已损坏，移到废纸篓”的问题，在 DMG 根目录直接放置 `双击一键修复打不开(已损坏解决).command`。
  - 用户拖入 Applications 后双击脚本即可自动执行 `xattr -cr "/Applications/AI Agent Hub.app"`，一秒完成解封。
- **官方下载页指引完善**：在下载官网显著位置与 FAQ 区域提供可视化解封教程与单行命令复制功能。
- **内置原生应用内热更新 (OTA In-App Updater)**：
  - 集成前端热更新管理器，应用启动 2 秒后自动静默探针检测 GitHub 最新 Release。
  - 发现新版时弹出专属升级模态框，支持应用内一键下载、验证与无缝重启，从第二版起彻底绕过浏览器下载导致的 Gatekeeper 拦截。

#### 4. 全链路白屏致命异常防御 (Stability & Anti-Crash)
- **数据结构版本隔离与降级兜底**：
  - 对所有从 `localStorage` 读取的数据添加 `try-catch` 与格式合法性校验，检测到旧版本脏数据或字段不兼容时自动平滑回退至默认配置，彻底消除运行时抛出未捕获异常导致的全白屏问题。
- **完善全局顶层错误边界**：
  - 配置 `FrontendErrorBoundary`，发生不可预期的渲染异常时展示诊断面板与“一键重新加载”按钮，杜绝死白屏。

#### 5. 安全合规与隐私深度清洗 (Security & Sanitization)
- **彻底清除开发者个人姓名与标识符**：
  - 侧边栏用户身份全面重构为中立的企业级标识 `未登录用户`，头像由个人简写改为统一的 `AI / 8x 专线` 图标。
  - 全局代码、注释、测试用例、提交差异及 Mock 数据中涉及的真实姓名全部清除。
- **清洗真实网络与 Token 数据**：
  - 彻底移除了源码及构建产物中残留的真实系统访问 Token、生产服务器内部 IP 等敏感信息，全部替换为标准中立的示例规范。

#### 6. 彻底根除重复热更新提示与推送虚警 (Unified Update Entry & Zero False Positives)
- **消除顶栏误导性状态与双重入口问题**：
  - 此前顶栏常驻「● 热更新就绪」并带有绿色指示灯，极易误导用户认为“已有新版本待安装”，点击后却提示“当前已是最新版本”；且侧边栏同时存在「🔄 热更新」按钮，导致同屏出现两个重复的更新入口。
  - **整改落地**：
    1. 顶栏更新胶囊调整为**严格条件渲染**：仅当检测到真实新版本（`hasPendingUpdate === true`）时才会高亮出现 `🔥 发现新版 vX.X.X`；无更新时顶栏完全收起，保持极简干净。
    2. 侧边栏废除突兀的悬浮大按钮，精简为底部单点版本号 `v4.2.1`（悬浮可手动检查更新，有新版时亮起微标橙点）。
- **重构双通道热更新检测机制**：
  - 引入 `compareSemver` 严格语义化版本比较，杜绝同版本或降级误报。
  - 增加 CDN 静态清单通道（`version.json` / `latest.json`），免鉴权、零 GitHub API 403 频控，实现静默、精准的版本探测与推送。

将应用从原 CC Switch 辅助工具中剥离，正式确立「AI Agent Hub」专属桌面客户端品牌与独立交互架构。

#### 核心变动
- **独立顶层桌面挂载**：解耦原有 CC Switch 复杂路由，直接以 `RelayApp` 作为应用唯一顶层窗口挂载。
- **WireGuard 零信任防封专线核心**：
  - 接入 NetBird WireGuard 专用出海通道（默认骨干网段 `100.64.0.12`）。
  - 支持多地域纯净住宅出口节点选择（美国西海岸、新加坡、东京）。
  - 新增 IPv6 旁路公网泄露拦截开关与实时 DNS 泄露探针检测。
- **官方下载落地页上线**：
  - 构建高品质 Tailwind 官方产品主页（`docs/index.html`）。
  - 支持一键部署至 GitHub Pages 与 Cloudflare Pages。
- **桌面与终端双模态唤起**：
  - 支持一键唤起系统已安装的桌面端（如 Claude、ChatGPT）。
  - 提供终端 CLI 自动化配置命令与环境变量注入。

## 四、版本发布质检核对清单 (Checklist)

每次发起版本交付前，开发与审查人员必须逐项确认以下标准：

| 检查项 | 验证标准 | 状态 |
| :--- | :--- | :---: |
| **产品场景** | 接入中心严格围绕海外 6 大前沿 Agent 工具，绝无国内消费级无关模型 |  |
| **数据一致性** | 接入中心配置状态与设备管理 Key 矩阵 100% 对应联动，重启持久化有效 |  |
| **安全脱敏** | 代码库全局搜索无开发者个人姓名、无客户真实 Token、无私有敏感 IP |  |
| **防白屏兜底** | 清除或篡改 `localStorage` 后启动应用，首屏依旧正常渲染且无未捕获异常 |  |
| **Gatekeeper 防护**| DMG 包含一键修复脚本，下载页提供清晰解除隔离指引 |  |
| **热更新通道** | 版本号规范对齐，更新检查接口超时与失败有完善兜底提示 |  |
| **自动化测试** | `pnpm run test:unit` 全部通过，生产构建 `pnpm run build:renderer` 零报警 |  |
| **版本记录更新** | `CHANGELOG.md` 与 `docs/ITERATION_LOG.md` 同步登记本次版本全部变动 |  |
